# Governance ordering + authoritative binding proof

Use when a gate demands proof that admission/binding **preceded** a mutation, or that an
"authoritative" ExecutionBinding/Profile existed before any write. Pair with SKILL.md rule 12(o)/(p).

## 1. Find the authoritative object BEFORE inventing one

Substituting a convention string (`X_LIFECYCLE`, `BOUND_VIA_Y`) for a real binding is a blocking
defect: a reviewer reads it as no binding at all. Search first.

Where the canonical object usually hides:
- the repo's operating rules file (`AGENTS.md`) — its reading-order list often names the exact
  WorkOrder/ExecutionBinding example path and schema id;
- the control-plane user-guide doc's "normal lifecycle" section — names the canonical schema id
  (e.g. `RP002-EXECUTION-BINDING/2`) and a live example binding id;
- a `var/<stage>/<pipeline>.py` that MATERIALIZES the object — the ground truth for its field shape.

Binding shape to reproduce (do not drop sections): `normative` (workorder_id, digests, authority
refs) / `routing` (topology_mode, profile_id, logical_role_id, task) / `delegation`
(delegation_id, issuer, assignee, allowed+denied scope, expiry) / `lease` / `budget` / `idempotency`
/ `runtime` (run_id, worker, workspace, candidate_write_set, evidence refs) / `terminal`.

`ROLE != PROFILE != WORKER`. Emit a separate profile effective-load readback; never infer the
profile from the role.

**Every window/limit/bound field carries a real value.** A delegation whose `issued_at == expires_at`
is a zero-duration window that authorizes nothing — reject it as a defect in your own artifact before a
reviewer does. Read the grant back from the governance store (the spine row), do not merely assert it.
The same rule covers empty `execution_disposition`, all-zero budgets, and any field whose value makes
the containing claim vacuous: `x present` must imply `x does something`.

If no authoritative object or equivalence contract exists, that is a typed blocker
(`TEMP_CLOSED_<X>_CONTRACT` with the exact missing authority) — not a licence to define a local one.

## 2. Monotonic ordering stream (never wall-clock)

Use ONE append-only event stream whose ordinal is generated by the governance system:
- `ProjectLifecycleController` (`src/hg_kseos/lifecycle.py`) writes `project_transitions` AND
  `canonical_events`; both are append-only tables with a DB-generated `rowid`.
- Real lifecycle vocabulary (use it; do not invent stage names): `PROJECT_CREATED` ->
  `SOURCE_DISCOVERY` -> `SOURCE_ADMISSION` -> `INTENT_BOUND` -> `REQUIREMENTS_READY` ->
  `DESIGN_READY` -> `PLAN_READY` -> `WORKORDERS_ADMITTED` -> `EXECUTING` -> `VERIFYING` -> ...
  plus side states `REPAIRING` / `BLOCKED_HITL` / `TEMP_CLOSED` / `FAILED` / `ROLLED_BACK` /
  `CANCELLED`.
- The edge `WORKORDERS_ADMITTED -> EXECUTING` is the natural boundary meaning "admission closed,
  mutation permitted"; the post-write transition (-> `VERIFYING`) closes the other side.

Read back and assert, not just print:
```sql
SELECT rowid, transition_id, from_state, to_state, trigger, created_at
FROM project_transitions WHERE project_id=? ORDER BY rowid;
```
- ordered: `seq(WORKORDERS_ADMITTED) < seq(MUTATION_PERMIT) < seq(FIRST_WRITE)`;
- contiguous: `sorted(rowids) == range(min, min+len)` — a gap invalidates the stream;
- writer cannot choose the key: `rowid` is DB-assigned on insert, so it cannot be backdated.

Demote every wall-clock value to supporting metadata and say so once, consistently, everywhere.
A receipt claiming `wall_clock_only: false` beside a residual list admitting a host-clock oracle is
a self-contradiction an independent lane finds immediately — reconcile all statements about the same
property before publishing.

## 3. Enforce the order structurally, in two processes

Narration is not enforcement. Split the round:
1. **admission process** — requirement/taskspec/workorder, binding, permit, freeze receipts. It must
   be incapable of writing candidate source.
2. **apply process** — its FIRST assertions, before any byte:
   permit artifact exists; it records `source_mutation_started: false`; `HEAD == baseline`; tree clean;
   permit seq > binding seq. Only then apply.

Byte-exact bounded replay: prefer `git checkout <rev> -- <paths over exactly the admitted set>`
over `git apply`. It is byte-exact, bounded, and sidesteps patch whitespace/CRLF failures (and the
`input=bytes` + `text=True` subprocess clash).

## 4. Pre-mutation receipts (freeze before any write)

- `PRE_MUTATION_ADMISSION_RECEIPT`: `subject_type: PRE_MUTATION_BASELINE_WORKORDER`,
  `direct_final_subject_match: false`, baseline + workorder + checkpoint, binding id/schema/hash,
  profile ref, permit id, admission+permit seqs, bounded write-set, `source_mutation_started: false`.
- `MUTATION_PERMIT_RECEIPT`: permit ties to workorder + baseline + admitted write-set; permit seq >
  binding seq; states it is REQUIRED by the writer route.
- `FIRST_MUTATION_ORDERING_RECEIPT`: the ordering key and its properties (generated_by, monotonic,
  append_only, contiguous, writer_cannot_choose_or_backdate), both seqs, the deterministic ordering
  statement, `wall_clock_is_primary_oracle: false`, and the `TRANSITIVE_MUTATION_LINEAGE` edge.

A pre-mutation artifact cannot contain the final subject sha — model that as transitive linkage,
never as a false direct match.

**Provenance must match the step that produced it.** A pre-mutation artifact must be GENERATED by the
admission process. Capturing the readback in the evidence step and labelling it pre-mutation is the
gate's own negative fixture (a stale RepoContext): the run is void even though every field looks
right. Capture it inside admission, and let the post-mutation side emit its own, separately named
artifact.

**When the correction target had to exist BEFORE the mutation, RE-RUN — do not edit.** Editing a
pre-mutation artifact after the write is retroactive fabrication and a lane will find it (receipt
mtime, missing prior-run rows, a head that is not a genuine child of the baseline). The honest fix is
a full re-run from the clean baseline against a **FRESH governed spine**: ordinals then start at 1, the
stream is provably contiguous and append-only with no prior-run residue, and every pre-mutation
artifact is regenerated by the step that is supposed to own it. Parameterise the spine DB path so a
clean re-run needs no manual cleanup.

## 5. Raw evidence, not summary booleans

A gate evidenced by `x_pass: true` in a summary is NOT evidenced. Persist each command's raw
stdout/stderr plus its own hash as a standalone artifact.

Compiler receipts: run all of lint / activation / acceptance / compile / duplication and keep each
raw output. Parse the verdict by scanning for a balanced JSON object (find `{`, try `json.loads` from
each position) — these tools pretty-print, so "parse the last line" yields `UNKNOWN` while the exit
code is 0.

Also emit: PD04 packet, raw taskspec/workorder/ECP rows, binding, profile readback, permit, ordered
event slice, bounded-diff/write-set receipt, gate-calibration rows (incl. explicit false-positive and
false-negative defences), focused negative/adversarial logs, and the exact-HEAD test logs.

## 6. Linkage modes for evidence items

Declare one per item: `DIRECT_FINAL_SUBJECT` | `TRANSITIVE_PRE_MUTATION_LINEAGE` |
`WORKORDER_CHECKPOINT` | `COMPILER_CONTRACT_BOUND` | `ENVIRONMENT_BOUND`. `DIRECT` only when the item
itself derives the final subject; otherwise transitive with an explicit `via` edge and
baseline/workorder/permit ids.

**Assign the mode by what the artifact actually derives, then check it by its OWN evidence.** A
contract-bound artifact (compiler receipts, their rendered outputs) has no git-HEAD subject at all —
forcing it into `DIRECT_FINAL_SUBJECT` makes your own validator emit a false `invalid_direct_link_count`
and blocks your own publish. Check it by its contract evidence instead (does the receipt contain
`PROMPT_COMPILE_PASS`). Keep one counter PER class; a single mixed counter both over- and under-reports.
The mirror trap: a `REQUIRED` list built from an assumed filename stem marks a present artifact
missing — build it from the artifacts' actual names.

Remote readback must report ALL of these as 0, not just the hash count:
`hash_mismatch_count`, `byte_mismatch_count`, `invalid_direct_link_count`,
`invalid_transitive_link_count`, `missing_required_evidence_count`.

And when an independent lane's denominator disagrees with yours, reproduce the EXACT logged invocation
before either side claims correctness — a lane's scratch harness using a different top-level dir
under-reported 106 against a true 113. Both sides can be wrong; the logged command is the arbiter.
When force-pushing a re-run onto a branch that already has an open PR, LOOK UP that PR and reuse it
rather than POSTing a duplicate (the API rejects the duplicate, and opening a second PR for the same
branch muddies the acceptance history).
