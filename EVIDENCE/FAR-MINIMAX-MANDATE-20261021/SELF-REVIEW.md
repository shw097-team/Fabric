# 自我研究：這一回合的缺陷是怎麼被找到的

**回合**：FAR-MINIMAX-MANDATE-20261021
**問題**：本回合的自檢測（drift gate + 目標測試套件）最後是綠的。那麼，綠的時候還藏著什麼？

這個問題值得回答，因為它決定了下一回合的檢測 effort 該放在哪裡。

## 量化的結局

| 項目 | 數值 |
|---|---|
| 全庫測試 BEFORE | `8 failed, 436 passed, 90 subtests passed` |
| 全庫測試 AFTER | `8 failed, 436 passed, 90 subtests passed` |
| 本回合引入的新失敗 | **0** |
| registry 欄位重建數 | 21（兩輪同步合計） |
| 找到並修好的缺陷 | **4** |

綠的測試與 4 個已修好的缺陷並存——這不是矛盾，這是**檢測範圍**的證據。

## 四個缺陷，分別是誰找到的

### D1 — registry 的 route rows 宣告舊模型，而 drift gate 回 `[]`

**找到方式**：人工跨欄位稽核（把 registry 的 routes 逐欄對照 pool）
**自動閘門為何漏掉**：`check_drift` 比對的是「registry 的 **projections** vs 現場」。
它**從不**比對「registry 自身的 route rows vs pool」。
一個只要跟著 pool 的 projection 走、但自己內部仍留著舊 arm 的 registry，照樣通過。
**修法**：`apply_registry_route_sync.py` 從 pool 重建那些欄位（15 欄）。
**殘留缺口**：這個同步是**獨立的腳本**，還沒接進 `check_drift`。
下一次改 pool 而忘了跑它，D1 會靜默重現。

### D2 — route row 頂層還有一份 auth posture 的副本

**找到方式**：**獨立 AO**，check 4，跑在**提交位元組**上
**自動閘門為何漏掉**：D1 的修法只覆蓋了 D1 的稽核看過的那些欄位。
**同一份事實存在於同一份記錄的另一個位置**，對任何針對第一份副本位置寫的檢查器都是隱形的。
**修法**：同步腳本也從 pool 推導 route-level posture（6 欄）。
**殘留缺口**：這類缺陷的根源是「一個事實存兩份」。
一般性的修法是讓 route row 變成**衍生**而非**編輯**的產物，讓它只有一份。

### D3 — 測試 stub 硬編 canonical pool 的 rank-1

**找到方式**：全庫 AFTER 跑（隔離比對）
**自動閘門為何漏掉**：錯的是**測試套件本身**，所以任何「對套件的閘門」都報不出來。
**修法**：stub 改為從 dispatcher 傳給 child 的 `--model` 推導 provider/model——
**被派發的臂就是被回報的臂**。同時把 `tests/fixtures/` 納入版控。
**殘留缺口**：此類無已知缺口——耦合是被移除的，不是被繞過的。

### D4 — `tests/fixtures/` 未追蹤，讓比對的絕對數字失真

**找到方式**：看比對輸出時問「為什麼 baseline 有 26 個 lane 測試失敗」
**自動閘門為何漏掉**：**兩條腿都失敗的項目會從差集裡相消**。
比對因此回報「沒有新失敗」，而絕對數字整整差了 26。
**修法**：fixture 納入版控，並帶入比對的兩條腿。
**殘留缺口**：比對應該在「baseline 大比例不健康」時給出訊號，而不是讓共模失敗相消。

## 結論

**活下來的都是自檢測「結構上不可能看到」的缺陷**：
一個事實存兩份（D1、D2），以及一個把「今天 rank-1 是誰」寫死的測試（D3）。

四個缺陷裡：
- 1 個由**獨立 AO** 找到（工作在不同起點的 artifact 上，用不同清單）；
- 2 個由**人工跨欄位稽核**找到；
- 1 個由**自動化測試套件**找到；
- 1 個由**對自動化輸出的再閱讀**找到。

誠實的解讀是：**綠的 drift gate 加綠的目標測試套件，不是跨欄位一致性的證據**。
它只證明了閘門自己負責的範圍被滿足了。

這也解釋了為什麼 AO 值得成本：它找到 D2，而內部沒有任何閘門能找到 D2。
AO 必須跑在**提交位元組**上、用**自己的清單**——否則它只是把主執行者的結論再跑一遍。

## 建議的下一步（依價值排序）

1. **把 registry-vs-pool 的比對接進 `check_drift`**。
   把「記得去跑的腳本」變成「繞不掉的閘門」。這是單一價值最高的改動。
2. **讓 registry 的 route row 變成衍生產物**（generated, not edited），
   一個事實只有一份。這是移除 D1/D2 整個類別，而不是逐個 instance 修。
3. **在隔離比對裡加「baseline 不健康」訊號**：
   兩腿共有的失敗佔比過高時要出聲。
4. **保留 AO 跑在提交位元組上、用自己的清單**。它是整個回合最便宜的缺陷發現面。

## 誠實的天花板

這是對「本回合的檢測面找到什麼」的回顧。
**它不是驗收**，也**不宣稱缺陷清單是完整的**——
D2 是同一份記錄的第二層，那麼第三層可能還存在。
