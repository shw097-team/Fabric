# FAR-20261016-022 — Learning

1. **判「該不該併」只需一個問題：併入會實際加入什麼？** `git diff --shortstat origin/main...<branch>`
   為空即已被他路徑取代——這比讀 20 個回合的歷史快、也不靠記憶。取代性是**可量測**的，不是可爭論的。
2. **`merge-tree --write-tree` 讓衝突性成為唯讀量測**：不改工作區、不改索引，就能在裁決階段斷言
   「併入即需人工解衝突」。衝突＝違反低阻力，直接 `DO_NOT_MERGE`，不必細讀內容。
3. **證據分支的命名若不含字面 "evidence"，分類器就會漏判。** 我用「命名啟發 ＋ 頂層目錄形狀」雙條件才認出
   `closeout`／`readme` 家族；更重要的是**明示放行清單必須排在最前面**，否則 PR #18 這種名字含 "closeout" 的
   真候選會被誤歸為證據分支。**判準的順位就是判準的一部分。**
4. **合併前最貴的風險是「兩個都對的變更彼此破壞」。** 我的 docs 候選與 PR #18 同改 docs 家族：先用對照組
   證明各自無辜是不夠的，必須在**併後**組合上再跑一次守門測試。低阻力 ≠ 不驗，而是**驗在正確的層級**。
5. **高後果寫入要以「先測後推」的順序做**：本地合併 → 全套測試 → 單一 push。多數事故來自「先推再測」。
6. **Owner 可以覆寫其顧問的建議，但不可以被描述成顧問同意了。** 報告要求人類合併；Owner 改派代理人執行——
   證據裡寫的是 `OVERRIDDEN_BY_OWNER`，不是 `EXTERNALLY_ACCEPTED`。
