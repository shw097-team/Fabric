# FAR-20261016-022 — Decision Question（未併入 main 的候選：哪些建議直接併入）

**Round** `PIPD-UNMERGED-CANDIDATES-20261016`｜**前導** `FAR-20261016-021-repo-hygiene-and-handover`
**問題**：在 `origin/main` = `d3bd5456afbff21a8c8837994a49f57be3e1b97e` 之下，盤點**全部未併入 main 的候選**，
逐條給出「是否建議直接併入 main」的工程裁決 ＋ 執行方案，須同時滿足：

1. **低阻力** — 不製造衝突、不製造要人回頭收拾的中間態。
2. **高可行** — 以現有憑證與既有車道即可完成，且每一步可回讀驗證。
3. **高工程必要性** — 併入後 main 必須比現在**更真**（真實性）或**更完整**（缺件歸位），而不是更多。
4. **不過度工程化** — 併入本身不得附帶重構、重跑無關流程或順手改動。
5. **對齊上位** — 《S4 最終獨立驗收報告》§0 的 `MERGE_APPROVED_SCOPE_ONLY` 與 §8 的「不批准」清單；
   《S4 FINAL 指揮薄》§0 的 `merge_tag_release: OWNER_GATE_ONLY`。

**授權狀態（本回合的前提，逐字）**：用戶令「當FAR提出的最佳工程裁決建議+執行方案出來之後，**用戶授權同意
這些裁決建議**，並且你必須直接執行FAR提出的最佳工程裁決建議+執行方案。」
⇒ 這使 `OWNER_GATE_ONLY` 的**執行者**由 Owner 指派出本回合代行；**授權內容僅限 FAR 建議中列為建議併入者**，
不擴及 tag／release／資產替換。

**必須一併回答的第二問**：報告 §0 曾寫「需**一般人類**合併操作與新 merge commit 讀回」。Owner 現改以代理人
執行。此為 Owner 對其自身顧問建議的**明示覆寫**，須在裁決與證據中揭露，不得以「外部已接受」描述。
