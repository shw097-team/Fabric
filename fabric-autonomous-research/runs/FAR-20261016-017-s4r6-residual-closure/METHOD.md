# Method

1. **Gate-1 route.** Class `RESEARCH_LITERATURE_REPO` → `NATIVE_WITH_SELECTED_ARIS` /
   `FAR_ROUTE_NATIVE_ARIS`, taken through the live named-method registry
   (`src/hg_kseos/named_methods.py`, `registry_snapshot()` + `route(flow)`), with an unrelated flow as a
   negative control. Recorded in the round's `route_check` receipt.
2. **Two independent reconnaissance sub-agents, run in parallel with the writer lane.** They are not
   synthesizers: each writes one artifact from primary sources.
   - W1 residual universe: every residual / gap / blocked / owner-decision / unlanded item, with the
     locator it came from, de-duplicated across the R6 report, the round's own tickets, the R11
     handover and the prior FAR runs (014/015/016), plus live GitHub PR/release state.
   - W2 defect dossier: the checker capability gap (what the sandbox actually blocks, quoted from the
     dispatcher source) and the `VERIFY_SECURITY` pool ordering defect, each with receipts and an
     explicit "could not determine" section.
3. **The rule is derived from those artifacts plus the round's own measurements**, and is stated as a
   ranked action set where every action carries: friction, feasibility, necessity, an
   over-engineering ruling, the alignment claim, and the authority it needs.
4. **Execution of the ruling, not of a plan.** The owner pre-authorized execution, so every action the
   ruling marks executable-now is executed on the lane chain; every action marked owner-gated is
   *prepared* (one-action form) and not executed. The dividing line is authority, not difficulty.
5. **Writer and checker on different model axes.** EXECUTE on the Codex CLI arm
   `opencode-go/deepseek-v4.1-flash`; VERIFY_SECURITY pinned to `openai-codex/gpt-6.1-sol` at rank 2 with
   `--require-arm`, because the pool's rank-1 arm is the writer's own model. The registry is read, never
   edited, to make a measurement come out right.
6. **The checker is given the capability it lacked** wherever the lane contract permits it, so that its
   verdict is not bounded by a tooling limitation that this round can remove. Where it still cannot run
   something, that stays visible as its own NOT_RUN.
7. **Falsifiability first.** Any new guard landed into the product repository must ship with mutations
   that make it fail; a guard that only ever passes is not evidence and is rejected at review time.
8. **Every count derived from artifacts on disk**; the evidence pack is generated, not hand-written.
9. **Closeout and handover as first-class products**, not as an afterthought: a checkpoint carrying the
   exact subject identity, the open tickets, the owner decisions, the rollback pointer and the next
   legal action.
